## 🛠 آموزش ساخت پنل روی Railway

### مرحله ۱ — فورک کردن پروژه

1. وارد GitHub شوید و وارد صفحه‌ی ریپازیتوری پروژه شوید.
2. روی دکمه‌ی **Fork** (بالا سمت راست) بزنید.
3. روی **Create fork** بزنید تا یک کپی از پروژه در اکانت خودتان ساخته شود.

> همین کافی است؛ نیازی به آپلود یا ویرایش هیچ فایلی نیست. همه‌ی کتابخانه‌های لازم در اولین اجرا خودکار نصب می‌شوند.

### مرحله ۲ — ساخت پروژه در Railway

1. وارد Railway شوید و روی **New Project** بزنید.
2. گزینه‌ی **Deploy from GitHub repo** را انتخاب کنید.
3. ریپازیتوری فورک‌شده‌ی خودتان را انتخاب کنید.
4. صبر کنید تا دیپلوی اولیه تمام شود.

### مرحله ۳ — گرفتن دامنه

1. در **Settings** به بخش **Networking** بروید.
2. روی **Generate Domain** بزنید.
3. آدرسی شبیه این می‌گیرید:

```
https://your-panel-production.up.railway.app
```

### مرحله ۴ — اتصال Volume (بسیار مهم ⚠️)

بدون Volume، با هر دیپلوی جدید اطلاعات (کانفیگ‌ها، کاربران، کلید نود) پاک می‌شود.

1. در پروژه روی **New → Volume** بزنید و آن را به سرویس وصل کنید.
2. مسیر Mount را بگذارید: `/data`
3. دیپلوی را دوباره انجام دهید.

### مرحله ۵ — ورود به پنل

1. آدرس دامنه را در مرورگر باز کنید.
2. وارد صفحه‌ی ورود شوید.
3. در اولین ورود، **رمز عبور اولیه** را خودتان تنظیم می‌کنید (رمز پیش‌فرض وجود ندارد).

---

## ⚙️ متغیرهای محیطی (اختیاری)

در Railway از بخش **Variables** می‌توانید این‌ها را تنظیم کنید:

| متغیر | توضیح |
|---|---|
| `ADMIN_PASSWORD` | رمز ورود پنل. اگر خالی باشد، در اولین ورود از شما رمز می‌خواهد |
| `SECRET_KEY` | کلید امضای نشست‌ها. با تنظیم آن، بعد از هر دیپلوی لاگین باقی می‌ماند |
| `NODE_API_KEY` | کلید ثابت API نود (برای مولتی لوکیشن، پایین‌تر توضیح داده شده) |
| `TELEGRAM_BOT_TOKEN` | توکن ربات تلگرام (از [@BotFather](https://t.me/BotFather)) |
| `TELEGRAM_ADMIN_IDS` | آیدی عددی ادمین‌های ربات (با کاما جدا کنید) |
| `DATA_DIR` | مسیر ذخیره‌ی اطلاعات (پیش‌فرض `./data`؛ روی Railway از Volume استفاده می‌شود) |
| `PORT` | پورت اجرا (Railway خودش تنظیم می‌کند) |

---

## 🤖 راه‌اندازی ربات تلگرام

1. به [@BotFather](https://t.me/BotFather) بروید و با `/newbot` یک ربات بسازید.
2. توکن را کپی کنید و در Railway به‌عنوان `TELEGRAM_BOT_TOKEN` بگذارید.
3. آیدی عددی خودتان را از ربات‌هایی مثل [@userinfobot](https://t.me/userinfobot) بگیرید و در `TELEGRAM_ADMIN_IDS` بگذارید.
4. سرویس را Redeploy کنید.

## 🔄 آپدیت پنل

1. وارد ریپازیتوری فورک‌شده‌ی خودتان در GitHub شوید.
2. روی **Sync fork** و بعد **Update branch** بزنید.
3. Railway به‌صورت خودکار دوباره دیپلوی می‌کند.
4. اگر Volume وصل باشد، اطلاعات شما حفظ می‌شود.

## 🌍 آموزش مولتی لوکیشن

با مولتی لوکیشن، یک پنل اصلی (**Master**) چند پنل دیگر را به‌عنوان **نود** در کشورهای مختلف مدیریت می‌کند. کاربر با یک لینک اشتراک، به چند لوکیشن دسترسی دارد.

> هر پنل AHB هم می‌تواند Master باشد و هم Node. نود فقط یک AHB Panel دیگر است که روی سرور/ریجن متفاوتی اجرا می‌شود.

### 🧠 ساختار

```
            ┌────────────────────┐
            │   پنل اصلی (Master) │
            └─────────┬──────────┘
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
   نود ۱ (هلند)   نود ۲ (سنگاپور)   نود ۳ (آمریکا)
```

### مرحله ۱ — ساخت پنل‌های نود

برای هر لوکیشن، یک پروژه‌ی جدید در Railway بسازید و **همان ریپازیتوری فورک‌شده** را دیپلوی کنید. نکته‌ها:

- هر نود را در **ریجن متفاوتی** بسازید:
  `Settings → Deploy → Region`
- برای هر نود دامنه بگیرید (`Generate Domain`).
- برای هر نود Volume با مسیر `/data` وصل کنید.

### مرحله ۲ — برداشتن کلید API هر نود

1. وارد پنل **نود** شوید.
2. از منو به صفحه‌ی **نودها** بروید.
3. در کارت **کلید API این پنل**:
   - آدرس پنل را کپی کنید
   - روی **نمایش** و بعد **کپی کلید** بزنید (کلید با `ahbn_` شروع می‌شود)

> 💡 **ثابت نگه‌داشتن کلید:** اگر Volume وصل نباشد، کلید با هر دیپلوی عوض می‌شود. یا Volume وصل کنید، یا در Variables نود متغیر `NODE_API_KEY` را با یک مقدار ثابت بسازید.

### مرحله ۳ — افزودن نود به پنل اصلی

1. وارد پنل **Master** شوید و به صفحه‌ی **نودها** بروید.
2. در کارت **افزودن نود** این‌ها را پر کنید:

| فیلد | مقدار |
|---|---|
| آدرس پنل نود | `https://my-node.up.railway.app` |
| کلید API نود | کلیدی که از نود کپی کردید (`ahbn_...`) |
| نام | اختیاری؛ اگر خالی باشد، از ریجن سرور تشخیص داده می‌شود |

3. روی **تست اتصال و افزودن** بزنید.
4. پیام موفقیت و تأخیر (Ping) نود نمایش داده می‌شود.
5. همین کار را برای بقیه‌ی نودها تکرار کنید.

### مرحله ۴ — ساخت کانفیگ مولتی لوکیشن

1. در پنل Master وارد **ساخت کانفیگ** شوید.
2. پروتکل را روی **مولتی لوکیشن (Multi Location) 🌍** بگذارید.
3. حجم و تاریخ انقضا را تنظیم و کانفیگ را بسازید.
4. لینک اشتراک (Sub) را برای کاربر بفرستید.

کاربر با وارد کردن لینک اشتراک در کلاینت (v2rayNG، Hiddify، Streisand و ...)، لیستی از همه‌ی لوکیشن‌ها را می‌بیند و هر کدام را که خواست انتخاب می‌کند.

### 🔍 نحوه‌ی کار پشت صحنه

- Master هر ۱۰ ثانیه با نودها همگام‌سازی می‌کند.
- کانفیگ‌های مولتی لوکیشن از Master به نودها فرستاده می‌شود.
- مصرف هر کاربر از همه‌ی نودها جمع می‌شود و در Master نمایش داده می‌شود.
- حجم و انقضا روی همه‌ی لوکیشن‌ها یکسان اعمال می‌شود.

### ✅ نکات و عیب‌یابی

- **کلید API اشتباه است:** کلید را دوباره از پنل نود کپی کنید. اگر Volume نبود، کلید عوض شده است.
- **آدرس به جای دیگری هدایت می‌شود:** آدرس نهایی را با `https://` و بدون اسلش آخر وارد کنید.
- **این آدرس پنل AHBPanel نیست:** نود باید نسخه‌ی جدید پنل را اجرا کند؛ فورک را Sync کنید.
- **تأخیر بالا:** ریجن نود را به لوکیشن نزدیک‌تر به کاربران تغییر دهید.
- هر چند وقت یک‌بار آپدیت پنل را روی **همه‌ی** نودها و Master با هم انجام دهید تا نسخه‌ها یکی باشد.
